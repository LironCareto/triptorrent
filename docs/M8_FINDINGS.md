# M8 Findings

Status records describe the M8 implementation at the tested revision. “Does not block M9” assumes a controlled, explicitly experimental testnet.

| ID | Severity | Class | Component | Reproduction | Impact and resolution | Residual risk | M9 |
|---|---|---|---|---|---|---|---|
| M8-F001 | High | implementation bug | relay | `malformed_registration_and_oversized_frame_fail_closed`; `slow_registration_does_not_block_other_routes` | A malformed registration could terminate `serve`, while a slow registration blocked its accept loop. Bounded registration handlers now isolate both. | Listener accept failure can still stop the service. | Does not block |
| M8-F002 | High | missing resource bound | relay | `hostile_routes_are_bounded_cleaned_and_not_reused` | Route squatting could grow pending state indefinitely and stall forwarding threads. Pending/active counts, frame size and pending lifetime are now explicit; duplicate roles and route reuse fail closed. | Unauthenticated clients can consume the bounded capacity and cause denial of service. | Does not block |
| M8-F003 | Medium | missing resource bound | M2 bootstrap | `hostile_registration_and_route_storms_are_bounded`; `malformed_control_connection_does_not_stop_bootstrap` | Peer, relay, advertisement and assignment storms could grow memory. Registry and handler limits now reject excess state before queuing, and malformed handlers are isolated. | Spoofing and capacity exhaustion remain possible within M2. | Does not block |
| M8-F004 | Medium | implementation bug | node storage | `corrupt_database_identifiers_cannot_escape_managed_storage` | A corrupt database identifier reached path construction during deletion. IDs and numeric rows now fail closed before managed paths are derived. | A hostile local process that can rewrite the database already crosses the local trust boundary. | Does not block |
| M8-F005 | Medium | missing resource bound | M6 interop | `parser_limits_deep_wide_and_oversized_inputs` | Wide/large bencoding and magnets allowed excessive work. Input, depth, node, parameter and path limits now reject early. | CPU remains proportional to accepted bounds; Unicode collision policy is conservative. | Does not block |
| M8-F006 | Medium | implementation bug | content/resume | `hostile_manifest_shape_is_rejected_before_transfer_allocation`; `resume_rejects_impossible_bitmap_and_partial_lengths` | Hostile lengths and malformed resume state could trigger large sparse files or unsafe arithmetic. Manifest/content/state bounds and exact partial/bitmap validation now run before allocation or promotion. | The 32 GiB prototype cap is an implementation policy, not a normative protocol limit. | Does not block |
| M8-F007 | Medium | missing resource bound | local API | `node_local_api_rejects_adversarial_requests_and_survives` | Unbounded handlers and ambiguous HTTP parsing enabled local resource pressure/request confusion. Connections, headers, target, body and error output are bounded; duplicate length/auth headers and trailing requests fail closed. | The hand-written HTTP/1.1 server remains prototype-only and unauthenticated reads expose local metadata. | Does not block |
| M8-F008 | Medium | implementation bug | SQLite recovery | `corrupt_transfer_numeric_state_fails_closed` | Negative or unknown stored values could be coerced into plausible state. Row fields now validate strictly. | SQLite file corruption may still make the node unavailable until restored. | Does not block |
| M8-F009 | High | architectural risk | discovery | `m8_seeded_monte_carlo_is_reproducible_and_covers_all_candidates` | Targeted Sybils and contaminated routing tables produce material eclipse/linkage in the model. Diverse replicas and paths help but do not remove the risk. | Identity cost, churn and Internet topology are not modeled adequately for production. | Does not block controlled M9 |
| M8-F010 | High | architectural risk | traffic privacy | `m8_traffic_experiment_is_reproducible_and_metadata_only` | Size and cadence classify all six modeled transfer shapes; timing links control and relay activity. No M8 protocol redesign was attempted. | Padding, cover traffic, batching and multi-hop policy remain research tasks. | Does not block labelled M9 |
| M8-F011 | Medium | known prototype limitation | M2 control | threat model and registry abuse suite | Registrations, provider keys, relay claims and failure reports can be spoofed; deterministic selection can be biased. Bounds limit damage but add no authentication. | M2 remains centralized scaffolding and must not support anonymity claims. | Does not block controlled M9 |
| M8-F012 | Informational | research limitation | experiments | deterministic examples | Monte Carlo percentages and synthetic traffic timing do not predict the public Internet. Reports now label their assumptions and preserve seeds. | Live-testnet measurement and independent model review are still required. | Does not block |
| M8-F013 | Low | test-harness issue | conformance vectors | `experimental_m8_conformance_vectors_match_current_codec` | The initial `SwarmComplete` vector used `0x0a`; the implemented enum discriminant is `0x09`. The checked-in vector was corrected. | The vectors describe draft behavior and are not normative. | Does not block |
| M8-F014 | Low | test-harness issue | fuzz runner | `cargo check --manifest-path fuzz/Cargo.toml`; Linux `fuzz-smoke` CI job; Windows `protocol -runs=100` | The Windows runner appeared not to terminate because `clang_rt.asan_dynamic-x86_64.dll` was absent from `PATH`. Adding the Visual Studio MSVC AddressSanitizer directory allowed the campaign to complete normally; the runbook now documents the setup. CI runs fixed-count Linux smoke campaigns and stable property tests remain cross-platform. | Windows campaigns require the optional Visual Studio AddressSanitizer component and its runtime directory on `PATH`. | Does not block |

No critical finding remains open. No new ADR was added because M8 enforced bounds and validated existing decisions without changing the architecture.
