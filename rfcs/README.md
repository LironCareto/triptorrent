# TripTorrent RFC Process

Protocol changes that affect interoperability should be proposed as RFCs.

## Lifecycle

`draft` → `discussion` → `accepted` / `rejected` / `withdrawn`

## RFC contents

Each RFC should include:

- problem statement;
- proposed protocol change;
- wire-format or state-machine impact;
- privacy and security implications;
- compatibility implications;
- alternatives considered;
- migration/versioning strategy;
- test requirements.

Accepted RFCs should result in corresponding specification and conformance-test updates.
